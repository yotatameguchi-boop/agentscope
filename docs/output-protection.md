# 出力保護の評価と改良の記録

AgentScope は、どの経路から入った値でも、レポート（ターミナル・JSON）を返す直前に出力保護（`src/util/protect.ts`）を通します。
このドキュメントは、出力保護を評価データと実データで測り、改良した経過の記録です。

## 測り方

| 名前 | 内容 | 実行方法 |
| --- | --- | --- |
| 評価データ | 秘密情報 54 形式 × 置き場所 19 種 × 3 シード（3,078 件、`test/bench/corpus.ts`）と、無害な文字列 180 種 × 20 シード（3,600 件、`test/bench/negatives.ts`）。無害な文字列は「変更してはいけない（keep）」167 種と「伏せても許容できる（tolerable）」13 種に分ける。ダミーの値は固定シードの乱数で実行時に組み立てる | `npm run eval:protect` |
| 公開データ | このリポジトリの `node_modules`（package.json・README など 9,590 文字列）。ロックファイルでバージョンが固定されるため CI でも同じ内容になり、許容できる変更以外があれば失敗する（`test/protect-public-data.test.ts`） | `npm test` |
| 実データ | 指定したディレクトリの設定ファイル・ロックファイル・ワークフロー・README などから集めた文字列。変更された件数と、伏せた後の文字列だけを表示する（元の値は表示しない）。`--node-modules` を付けると node_modules も読み、公開データなので元の文字列も表示する | `npm run eval:protect-real -- [--node-modules] <dir>` |
| 処理時間 | 意地の悪い入力（ReDoS）と、部品を組み合わせた総当たりで、長さに対して時間が二乗に伸びないかを測る | `test/protect-performance.test.ts` |

- **再現率**: 秘密情報が出力から消えた割合。値そのもの、または値の半分以上の長さの断片が残っていたら「漏れた」とみなす
- **適合率**: 無害な文字列が変更されなかった割合。下の表の 12 回目までは 47 種の評価データでの値
- 品質の下限は `test/protect-quality.test.ts` で回帰テストにしている

### 処理時間（ReDoS）で見つかった問題

| 入力 | 修正前 | 原因 | 修正 |
| --- | --- | --- | --- |
| `https://aaaa…:bbbb…`（`@` のない長い URL、20 万文字） | 36 秒 | URL のスキームを、英字の列のあらゆる位置から照合し直していた | スキームは英数字の直後から始まらない、という条件を追加 |
| 空白のない長い文字列に、ランダムなトークンが多数 | 二乗 | トークンごとに「URL の中か」を調べるため、先頭までさかのぼっていた | `/` を含むトークンだけ、最大 4,096 文字までさかのぼる |
| `eyJ-eyJ-…` | 二乗 | JWT の形式を、本体の文字の途中からも照合し直していた | JWT だけ、`_` `-` の直後からは照合しない |
| `a--a--…` | 二乗 | `--キー=値` のキー名が `--` をまたいで伸びていた | キー名の中で `-` を連続させない |
| `a://a://…` | 二乗 | URL のユーザー情報（パスワード）の長さに上限がなかった | ユーザー名・パスワードを 256 文字までに限る |
| `AGE-SECRET-KEY-1@` の繰り返し（25 万文字） | 699ms（CI では 1.6 秒） | 公開コンテンツの URL かを調べるため、トークンごとに最大 4,096 文字さかのぼっていた（20 回目までの除外の追加で表に出た） | 文字列ごとに `://` の位置を1回だけ求め、トークンの位置に合わせて進める → 11ms |

部品 58 種の 2 つ・3 つの組み合わせ 9,481 通りで、長さを 2 倍にしたときの時間の伸びを測り、二乗のものがないことを確認した。

### 実データで残る 20 件

すべて伏せるのが妥当と判断したもの。

- 開発用 DB のパスワード（`POSTGRES_PASSWORD: …`、`postgres://user:<値>@…`、`.env.example` の実際の値）
- `Authorization` ヘッダーの値
- 「リンクを知っていれば開ける」URL の ID（`claude.ai/artifact/<id>`、`ai.studio/apps/drive/<id>`）。ID 自体が鍵の役割を持つため、ID の部分だけを伏せる

## 方針として伏せないもの

| 対象 | 理由 |
| --- | --- |
| 手がかりのない場所にある 16 進の値（32・40 文字など） | git のコミットハッシュ、ダイジェスト、チェックサムと区別できない。`--token`、`API_KEY=`、`"api_key":` などの手がかりがあれば伏せる |
| 手がかりのない場所にある 16 文字未満の値 | 一般の文字列と区別できない。検出で秘密情報と判定された値なら、保管庫により別の場所でも伏せる |
| 大文字・小文字・数字のどれかを含まないランダムな値 | 小文字だけの名前やハッシュと区別できない |
| 人が付けた名前（キャメルケース、ハイフン・アンダースコアでつないだ単語） | 誤検知が多いため |

## 残る制約

- 乱数を含む入力の誤検知は、評価データの固定シードでは見つからないことがある（12 の例）。乱数を変えて大量に試す確認を併用する

- 無害な文字列は 161 種と公開データで測っているが、他の環境の設定では誤検知が出る可能性がある。誤検知の例を見つけたら `test/bench/negatives.ts` に足して測り直す
- 見えない文字を挟んだ値を伏せた場合、その文字列からは見えない文字が取り除かれる（取り除いた形で判定し直すため）
- 値を逆順にする、空白で区切る、base64 で包み直すといった変換をした秘密情報は判定できない（設定ファイルに書かれる値としては想定しない）
